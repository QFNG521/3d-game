## 1. 设计分辨率与安全区

**结论**：以 720×1280 为唯一设计基准，所有坐标基于此；异形屏靠「安全区 + 等比适配」兜底，不单独出图。

| 项 | 值 | 依据 |
|---|---|---|
| 设计基准 | 720×1280（9:16） | 主流安卓/iOS 竖屏公约数，资源体积可控 |
| 顶部安全区 | 44px | 刘海/状态栏避让（iPhone 全系 + 安卓挖孔） |
| 底部安全区 | 56px | Home Indicator / 导航条避让 |
| 左右安全区 | 24px | 单手拇指可达区外缘留白 |
| 主内容区 | x:24–696（宽 672）/ y:68–1200（高 1132） | 顶安全区下 +24 留白，底安全区上 +24 留白 |
| 像素栅格 | 8pt 基准（所有尺寸取 4 的整数倍） | 避免半像素模糊与缝隙 |

## 2. 栅格系统

**结论**：4 列栅格 + 16px 槽距 + 24px 外边距，所有卡片/按钮贴栅格，组件尺寸为 8 的倍数。

| 项 | 值 |
|---|---|
| 外边距 M | 24px（3U） |
| 列数 | 4 列 |
| 槽距 G | 16px（2U） |
| 列宽 | (720 − 24×2 − 16×3) ÷ 4 = **156px** |
| 基准单位 U | 8px |
| 圆角阶梯 | 小 8 / 中 14 / 大 20（弹窗用 20） |
| 描边 | 2px 实线（卡其描边 Line 色） |

列 x 坐标（左缘）：C1=24，C2=24+156+16=196，C3=368，C4=540，右缘=696。

## 4. 字号阶梯（Type Scale）

**结论**：五档阶梯，数值类用等宽数字（tabular-nums）防抖动；正文 22px 在 720 基准下约等效真机 11pt，清晰可读。

| 档 | 字号 | 字重 | 行高 | 用途 | 依据 |
|---|---|---|---|---|---|
| 标题 Title | 36px | 800 | 1.2 | 界面大标题、弹窗标题 | 与资源数值拉开层级 |
| 副标题 Sub | 28px | 700 | 1.3 | 区块标题、设施名 | 次级锚点 |
| 正文 Body | 22px | 500 | 1.5 | 说明、列表项 | 720 基准下等效 ≈11pt，最小可读 |
| 辅助 Caption | 18px | 400 | 1.4 | 注释、单位、状态 | 不承载关键信息 |
| 数值 Number | 28px | 800 | 1 | 资源计数（tabular-nums） | 一眼可读，等宽防跳动 |

字体：`"PingFang SC","Hiragino Sans GB","Microsoft YaHei",system-ui,sans-serif`（系统字体，免授权；图内不放文字，全部引擎渲染）。

## 5. 点击区与反馈节点

**结论**：最小点击区 88×88（11U），主按钮视觉高 96、点击区含 padding 扩展至 104；即时反馈 ≤ 0.1s，结算/弹窗 ≤ 0.3s。

| 元素 | 视觉尺寸 | 点击区 | 说明 |
|---|---|---|---|
| 主按钮（出发/建造） | 高 96 × 宽按栅格 | 96×104（含 padding） | 全宽或半宽，Accent 填充 |
| 次按钮（取消/返回） | 高 80 | 88×88 | BG-2 + Line 描边 |
| 图标按钮（地图/背包） | 96×96 | 96×96 | 四态必全 |
| 设施卡 | 156×156（1 列） | 整卡 | 点按进入升级 |
| 列表行 | 高 112 | 整行 | 抉择选项/任务项 |

反馈节点（对应 PRD §3.2 / core-loop §五）：开箱/搜刮 0.1s 粒子+音效；建造完成 0.3s 外观变化；离线回归结算弹窗。

## 10. 图标家族规则（MVP 最小清单）

**结论**：五要素先定再批量；尺寸阶梯 48/64/96/128，小尺寸单独简化（不缩放充数）。

**五要素（同源）**：① 块面+2px 描边风格；② 正视微 2.5D 等距视角；③ 圆角 6–8px；④ 留白率 18%（图形占画布 82%）；⑤ 光源左上 45°，高光统一暖白。

**尺寸阶梯**：48（HUD 小标）/ 64（列表）/ 96（图标按钮）/ 128（设施大图）。

**MVP 图标清单**：
- 资源(5)：`ic_food` `ic_water` `ic_wood` `ic_metal` `ic_blueprint`
- 设施(4)：`ic_warehouse` `ic_purifier` `ic_farm` `ic_workshop`
- 通用(6)：`ic_menu` `ic_setting` `ic_bag` `ic_map` `ic_back` `ic_plus` `ic_lock`

命名：`<ic|btn|panel>_<name>[_<state>]@<scale>.png`，例 `btn_primary_normal@2x.png`、`ic_food@2x.png`。

## 12. 多分辨率适配表

**结论**：设计稿唯一基准 720×1280；运行时等比 scale-to-fit + letterbox，逻辑坐标不变，安全区动态取最大值。

| 目标分辨率 | scale | 策略 |
|---|---|---|
| 720×1280（基准） | 1.0 | 直接映射 |
| 750×1334（iPhone） | ≈1.04 | fit 高度，左右 letterbox ≤4px |
| 1080×1920（FHD） | 1.5 | @1.5 资源或运行时放大 |
| 1080×2340（全面屏） | fit 高度 | 顶部/底部安全区取 44/56 与异形区较大值 |

适配风险：极宽/极窄屏拉伸 → 用 `fit` 而非 `fill`，黑边可接受；文本按最长语种（德/俄）留 30% 余量。

## 13. 原生 Canvas / HTML5 落地配置

> 专家不写运行时脚本，但给可直接照抄的初始化与九宫格切绘方案（伪代码级）。

**画布初始化**：
```
// 逻辑坐标固定 720×1280；物理像素 = CSS尺寸 × dpr
const DESIGN_W = 720, DESIGN_H = 1280;
function resize() {
  const dpr = window.devicePixelRatio || 1;
  const cssW = container.clientWidth, cssH = container.clientHeight;
  canvas.width  = cssW * dpr;
  canvas.height = cssH * dpr;
  const scale = Math.min(canvas.width / DESIGN_W, canvas.height / DESIGN_H); // fit
  // 计算 letterbox 偏移 ox, oy 使逻辑(0,0)居中
  ctx.setTransform(scale, 0, 0, scale, ox, oy);
}
window.addEventListener('resize', resize);
```
**九宫格切绘**（给定具名边界 l,t,r,b）：
```
function draw9Slice(ctx, img, dx,dy,dw,dh, l,t,r,b) {
  const sx=img.width, sy=img.height;
  const cw=sx-l-r, ch=sy-t-b;          // 中区源尺寸
  const dwC=dw-l-r,  dhC=dh-t-b;       // 中区目标尺寸
  // 9 区: 上左/上/上右/左/中/右/下左/下/下右
  // 固定区 1:1 绘制, 中区拉伸
  blit(img,0,0,l,t,            dx,dy,l,t);
  blit(img,l,0,cw,t,           dx+l,dy,dwC,t);
  blit(img,sx-r,0,r,t,         dx+l+dwC,dy,r,t);
```
